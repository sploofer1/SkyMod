SkyMod · Конструктор попапа

Документация

Как устроен конструктор, что ему можно передать и что он умеет.

Что это

Отдельная страница-конструктор SkyMod (открывается из вкладки «Конструктор» в самом попапе, кнопкой «⤢ Открыть конструктор»). Сверху — переключатель «Попап» / «Сайт»: это два независимых конструктора на одной странице, показан всегда только один.

  • Попап — свой HTML/CSS/JS рисуются в песочнице поверх/под интерфейсом попапа расширения. Работает, только пока попап открыт.
  • Сайт — то же самое, но на настоящей странице avatar.skyeng.ru, пока она открыта — попап можно закрыть.

В обоих: можно полностью заменить встроенную анимацию своей, добавить виджет, мини-игру, часы, счётчик — что угодно, что умеет обычная веб-страница.

Как это устроено (и почему это безопасно)

Ваш JS выполняется не в самом попапе (и не на самом сайте), а в отдельном <iframe>, объявленном в манифесте расширения как sandbox page. Это единственное место во всём SkyMod, где вообще разрешено выполнять динамический код — обычные страницы расширения такого не позволяют по политике Chrome (CSP). У песочницы:

  • нет доступа к chrome.* API;
  • нет доступа к DOM самого попапа или сайта avatar.skyeng.ru — только к тому, что нарисовано внутри неё самой;
  • есть доступ только к тому, что ей явно передано (см. ниже) и к обычным веб-API браузера (canvas, DOM, таймеры, fetch и т.д. в пределах самого iframe).
Код хранится в chrome.storage.local только у вас и выполняется только у вас. Это тот же принцип, что у пользовательских скриптов в Tampermonkey или кастомных тем в Stylus — вы доверяете коду, который сами же написали.

Быстрый старт

  1. В попапе SkyMod откройте вкладку «Конструктор» и нажмите «⤢ Открыть конструктор» — откроется отдельная вкладка браузера со страницей конструктора. Она не закрывается при потере фокуса, в отличие от попапа, и там больше места под код.
  2. Переключателем сверху выберите «Попап» или «Сайт» — дальше всё ниже одинаково для обоих.
  3. Выберите пример в выпадающем списке рядом с «Вставить пример» — это заполнит HTML/CSS/JS рабочим кодом и сразу его запустит (видно в отладчике).
  4. Включите тумблер «Включить конструктор» / «Включить на сайте» слева, чтобы увидеть результат поверх/под настоящим интерфейсом (до этого момента можно спокойно отлаживать — код всё равно выполняется, ошибки видно).
  5. Правьте код — предпросмотр обновляется сам вскоре после того, как вы перестанете печатать, либо сразу по кнопке «▶ Применить» или Ctrl/Cmd+Enter прямо в поле кода. Tab и Shift+Tab там же — отступы (в т.ч. для целого выделенного блока строк), а не переход к следующему полю, как в обычном textarea.
  6. В режиме «Попап» — когда получилось что-то, к чему захочется вернуться, нажмите «+ Сохранить текущее» в «Пресетах конструктора» слева (пресеты пока только для попапа, не для сайта).

Попап SkyMod запоминает, на какой вкладке вы были — при следующем открытии он откроется на ней же, а не на «Теме». Страница конструктора отдельно запоминает, какой режим («Попап» или «Сайт») был выбран последним.

Что вам передаётся

Ваш JS выполняется как тело функции с четырьмя аргументами:

function(root, canvas, storage, theme) {
    // ваш код
}
АргументЧто это
rootDOM-элемент — контейнер, куда вставлен ваш HTML. Ищите свои элементы через root.querySelector(...).
canvasПервый <canvas>, найденный в вашем HTML (или null, если его нет) — просто для удобства, чтобы не писать root.querySelector('canvas') каждый раз.
storageПерсистентное хранилище конструктора: storage.get(key), storage.set(key, value), storage.remove(key) — все три возвращают Promise. Данные сохраняются между открытиями попапа, в собственном пространстве имён (не пересекается с остальными настройками SkyMod).
themeОбъект с текущими цветами попапа: { accent, mod, pulse } (те, что настроены на вкладке «Попап»). Также доступен как window.SKYMOD_THEME.
scheduleЖивой объект с расписанием на сегодня: phase, current, next, color, dayProgress и др. Подробно в разделе «Расписание и темы по предметам». Также window.SKYMOD_SCHEDULE.

Функция очистки

Если вернуть из своего кода функцию — она будет вызвана перед следующим запуском (например, при повторном нажатии «Применить»). Используйте её, чтобы остановить requestAnimationFrame, очистить setInterval или снять слушатели событий — иначе старый цикл анимации продолжит работать параллельно с новым. 

let raf;
function frame() {
    // ...
    raf = requestAnimationFrame(frame);
}
raf = requestAnimationFrame(frame);

return () => cancelAnimationFrame(raf);

Отладчик

Любая ошибка — синтаксическая (код не скомпилировался), брошенное исключение (в т.ч. уже после успешного запуска — например, внутри requestAnimationFrame или обработчика клика) или необработанный отказ промиса (storage.get(...).then(...) без .catch()) — сразу появляется в блоке «Отладчик» на вкладке конструктора: с текстом ошибки, номером строки (если его удалось определить) и стеком вызова в раскрывающемся блоке. Открывать инструменты разработчика не нужно.

  • Клик по кнопке «строка N → перейти» переводит курсор на нужную строку прямо в текстовом поле JS.
  • Повторяющаяся ошибка (например, ломается каждый кадр анимации) не плодит новую запись — у существующей просто растёт счётчик «×N».
  • Список ограничен последними ~12 разными ошибками, чтобы не раздувать попап.

console.log

console.log/warn/error/info внутри вашего кода дублируются в отдельную панель «Консоль» на странице конструктора — тоже без devtools.

Настройки размещения

Ниже — для режима «Попап». В режиме «Сайт» то же самое, кроме «Область» — её там нет, «Сайт» всегда занимает всю страницу.

НастройкаЗначенияЧто делает
Слой Под интерфейсом / Поверх всего «Под» — то же место, где обычно дорожки платы (позади вкладок и текста). «Поверх» — рисуется выше всего интерфейса попапа.
Область Весь попап / Шапка / Тело с настройками Ограничивает песочницу конкретным прямоугольником: всем попапом, только областью шапки (где логотип «Mod») или только областью вкладок с настройками.
Взаимодействие с курсором Вкл / Выкл Код песочницы получает события мыши (mousemove, mousedown, mouseup, click, mouseleave). Со слоем «Под интерфейсом» их пересылает сам попап, и интерфейс при этом работает как обычно. Со слоем «Поверх всего» песочница принимает мышь целиком: кнопки и поля в вашем HTML кликаются, но интерфейс попапа под ней недоступен.
Про мышь и "Слой". "Слой" выбираете именно вы — конструктор его не подменяет. Если включено "Взаимодействие с курсором" и выбран слой "Под интерфейсом", мышь работает в вашем коде через обычные window.addEventListener('mousemove', ...) по всей области попапа, но кликать кнопки внутри самой песочницы нельзя: она только следит за курсором. Нужны кликабельные элементы в песочнице: выбирайте "Поверх всего".
Размер попапа. На вкладке «Попап» можно выбрать компактный (320 x 524), крупный (400 x 584, по умолчанию) или максимальный (480 x 598) размер. Chrome не даёт окну расширения быть больше 800 x 600. Предпросмотр в конструкторе повторяет выбранный размер. Для глобального CSS попапа это значит: ширина body и высота панели теперь задаются переменными --popup-w и --panel-h, поэтому не задавайте им фиксированные значения, а при необходимости читайте эти переменные.

Глобальный CSS: меняем реальный интерфейс попапа

Отдельное поле «Свой CSS для всего попапа» — это НЕ песочница. Тег <style> добавляется прямо в настоящий <head> попапа, поэтому этим CSS можно переопределить любые существующие стили SkyMod — включая анимацию переключения между вкладками. JS сюда не пускают, только валидный CSS — поэтому отдельной изоляции этому полю не требуется.

Переход между вкладками сейчас устроен так (упрощённо):

.tab-content.slide-from-right { animation: slide-in-right .28s var(--ease); }
.tab-content.slide-from-left  { animation: slide-in-left  .28s var(--ease); }
.tab-content.fade-in          { animation: content-in     .22s var(--ease); }

@keyframes slide-in-right { from { opacity:0; transform:translateX(16px);  } to { opacity:1; transform:translateX(0); } }
@keyframes slide-in-left  { from { opacity:0; transform:translateX(-16px); } to { opacity:1; transform:translateX(0); } }
@keyframes content-in     { from { opacity:0; transform:translateY(4px);   } to { opacity:1; transform:translateY(0); } }

Чтобы поменять анимацию — переопределите те же классы своим @keyframes под тем же именем (проще всего) либо полностью замените правило. Например, зум вместо слайда: 

.tab-content.slide-from-right,
.tab-content.slide-from-left {
    animation: my-zoom-in .25s ease !important;
}
@keyframes my-zoom-in {
    from { opacity: 0; transform: scale(.92); }
    to   { opacity: 1; transform: scale(1); }
}

Правила из этого поля добавляются в самом конце документа, но !important в примере выше всё равно не помешает — на случай, если у исходного правила специфичность окажется выше.

Фон сайта: canvas/JS прямо на Skyeng

Отдельная секция на странице конструктора — своя песочница, свой HTML/CSS/JS, свои "Слой"/"Взаимодействие с курсором". Ключевое отличие от основной песочницы: код выполняется не в попапе, а прямо на вкладке сайта (avatar.skyeng.ru), пока она открыта — можно закрыть попап совсем, эффект останется. Аргументы функции те же (root, canvas, storage, theme), но theme здесь содержит только theme.accent, и он фиксированный (#8b7cf6): акцентный цвет сайта в расширении не настраивается. На сайте нет отдельных цветов "Mod"/пульсов, это чисто попаповские переменные. Цвет текущего занятия берите из schedule.color.

Изменения применяются сразу на всех открытых вкладках сайта — обновлять их вручную не нужно (используется тот же механизм живой реакции на изменение настроек, что уже красит фон/карточки на лету). Сам сайт нельзя встроить в страницу конструктора для полноценного предпросмотра "как в реальности" — авторизованные страницы вроде Skyeng сами запрещают встраивание себя в чужой iframe. Вместо этого рядом с редактором показан честный предпросмотр: та же песочница, тот же код, без интерфейса сайта вокруг — чтобы отладить внешний вид и анимацию, держать вкладку сайта открытой для этого не обязательно.

Части интерфейса сайта: свой стиль для отдельного элемента

Кроме canvas-фона, конструктор умеет менять отдельные элементы настоящего интерфейса сайта, например светящуюся полоску «сейчас» в расписании. Каждый такой элемент называется частью интерфейса: у неё есть скриншот, название, по которому её понимает ИИ, и точные селекторы. Вам не нужно знать вёрстку сайта.

Как сделать свой стиль для части

  1. Откройте конструктор, переключитесь на режим «Сайт» и найдите блок «Части интерфейса сайта».
  2. Выберите часть в списке (сверяйтесь со скриншотом).
  3. Нажмите «Скопировать промпт для ИИ» и вставьте его в любой ИИ-чат.
  4. В конце промпта замените <опишите…> тем, что хотите, например: лазер — сделай линию розовой, а плашку полностью скруглённой.
  5. Скопируйте css-блок из ответа в поле под списком и включите переключатель «Применять». Стиль сразу появится на открытых вкладках сайта.
Как писать запрос. В промпт уже вшиты название части, её синонимы и селекторы, поэтому достаточно назвать её привычным словом (лазер, сейчас, полоска) и написать, что изменить. Хорошо: лазер — убери свечение, оставь тонкую линию 2px цвета акцента. Плохо: сделай красиво (ИИ не знает, что именно менять). Если ИИ просит прислать данные об элементе, пришлите то, что он просит.

Окна и диалоги сайта

Всплывающие окна сайта (например, окно занятия по клику на карточку) лежат не внутри приложения, а в отдельном слое .cdk-overlay-container в конце страницы. Поэтому стили колонок и карточек расписания на них не действуют, а правило для самого слоя затронет все окна сайта. Сужайте его через :has([data-test="student schedule slot popup"]). Фон диалогов задаётся переменными дизайн-системы (--ds-dialog-default-backgroundColor и т.п.), которые компонент объявляет на своём хосте: обычное :root { --ds-dialog-… } не сработает, переопределяйте их на самом app-schedule-slot-popup и с !important. Подложку за окном (размытие и затемнение) SkyMod рисует собственным слоем и не убирает родное затемнение сайта. Все эти сведения уже вшиты в промпт части «Окно занятия».

Доступные части

Если нужной части нет в списке

Список частей будет расти. Пока нужной нет, можно сделать стиль для любого элемента самому:

  1. Откройте сайт, нажмите F12 и на вкладке Elements нажмите Ctrl+F. Введите текст, который виден на экране у нужного элемента (например, «сейчас»). Если элемент нельзя выбрать курсором (у него pointer-events: none), поиск по тексту его всё равно найдёт.
  2. Правой кнопкой на найденном элементе → Copy → Copy outerHTML. Скопируйте также HTML пары родителей.
  3. Сделайте скриншот блока Styles этого элемента.
  4. Скопируйте общий промпт ниже, отправьте его ИИ вместе с HTML, скриншотом и описанием желаемого, а полученный CSS сохраните у себя и отправьте разработчику, чтобы элемент добавили в список частей: после этого у него появятся скриншот, название и своё поле в конструкторе.
Важно. Сайт периодически обновляется, и его классы с хэшами (вроде ng-c2556642706) меняются. Поэтому промпты опираются на атрибуты data-test и осмысленные классы. Если после обновления сайта стиль перестал работать, откройте часть заново: скорее всего, нужно обновить селектор в списке частей.

Готовые примеры

В выпадающем списке «Примеры» в режиме «Попап»:

  • Бегущая линия — синусоида на canvas с переливом цвета по времени. Хорошая замена дорожкам платы.
  • Частицы — простая система частиц, использует theme.mod для цвета.
  • Часы — живые часы поверх попапа, без canvas — просто DOM + setInterval.
  • Счётчик кликов (storage) — кнопка с интерактивом и storage.get/set, демонстрирует персистентность между открытиями попапа.

В режиме «Сайт» — свой список примеров (используют только фиксированный theme.accent и цвет занятия):

  • Звёздное небо — мерцающие точки на canvas, тёмный фон.
  • Бегущая линия — та же идея, что в песочнице попапа, но цветом акцента сайта.
  • Фон по расписанию — аврора цвета текущего урока и тонкие линии прогресса дня и урока. Показывает, как использовать schedule.

Расписание и темы по предметам

Расширение читает карточки занятий на странице расписания (предмет, название, время), запоминает расписание на сегодня и каждые 15 секунд считает, что идёт сейчас. Оно сохраняется, поэтому тема работает и на других страницах сайта, а не только на самом расписании. Откройте страницу расписания один раз, чтобы данные появились.

Без кода: вкладка «Расписание» в попапе

  • Цвета предметов. Для каждого предмета, который расширение увидело, есть свой цвет. По умолчанию он подбирается автоматически и стабилен для предмета; кнопка ↺ возвращает автоцвет.
  • Цвет карточек по предметам. Каждая карточка красится в цвет своего предмета, прозрачность берётся из вкладки «Расписание».
  • Свечение под текущий урок. Фон подсвечивается цветом идущего урока (в перерыве и до начала занятий цветом ближайшего следующего). Цвет плавно перетекает при смене урока. Свечение видно при своём фоне (картинка или конструктор): под непрозрачным родным фоном сайта оно скрыто.
  • Окно занятия. Окно, которое открывается по клику на карточку. Включите «Настроить окно занятия», чтобы задать размытие и затемнение фона за ним. «Менять фон самого окна» красит панель окна выбранным цветом с нужной прозрачностью. Для более тонких правок используйте часть интерфейса «Окно занятия» в конструкторе (режим «Сайт»).
  • Сегодня по расписанию. Тут же видно, как расширение поняло ваше расписание. Если там пусто или время не совпадает с сайтом, расписание прочиталось неверно: сообщите разработчику.

В своём CSS: переменные

На странице сайта выставляются переменные --skymod-lesson-color (hex цвета текущего или ближайшего урока) и --skymod-lesson-rgb (тройка чисел для rgba(var(--skymod-lesson-rgb), 0.4)). Их можно использовать в CSS частей интерфейса, например, красить лазер в цвет урока. Когда урока нет, переменных нет, поэтому всегда пишите запасное значение: var(--skymod-lesson-color, #8a8f98).

В коде фона: аргумент schedule

Живой объект: ссылка не меняется, поля обновляются на месте, читайте их прямо в кадре анимации. Для реакции на смену урока есть событие window.addEventListener('skymod-schedule', e => ...). Работает и в песочнице попапа, и в фоне сайта.

phase"free" занятий нет, "before" до первого, "lesson" идёт урок, "break" перерыв, "after" после последнего.
colorЦвет для темы (hex): на уроке цвет урока, до начала и в перерыве цвет ближайшего следующего, иначе null.
currentИдущий урок или null: subject, title, startLabel, endLabel, color, progress (0..1), minutesLeft, start/end в мс.
nextБлижайший следующий урок или null: те же поля и minutesUntil.
previousПоследний закончившийся урок или null.
lessonsВсе занятия сегодня по времени.
dayProgress0..1 или null: сколько прошло от начала первого до конца последнего занятия.
remainingСколько занятий ещё не закончилось.
Всегда предусматривайте пустое расписание. Если вы ещё не открывали страницу расписания или сегодня занятий нет, ready === false, а current, next и color равны null. Фон должен выглядеть нормально и в этом случае. Готовый образец: пример «Фон по расписанию» в режиме «Сайт». Время читается из подписей карточек и считается по часам вашего компьютера.

Промпт для ИИ

Не обязательно писать код самостоятельно. Скопируйте блок ниже целиком в любой ИИ-чат (Claude, ChatGPT и т.д.), допишите в конце своими словами, что хотите получить, и отправьте — модель уже будет знать формат аргументов, ограничения песочницы и разницу между песочницей и глобальным CSS, без дополнительного промпт-инжиниринга с вашей стороны. 

Ты помогаешь писать код для конструктора расширения SkyMod (Chrome-расширение для сайта Skyeng/Skypro). У конструктора ДВА независимых механизма — используй тот, что подходит под задачу (или оба сразу):

1) ПЕСОЧНИЦА (поля HTML / CSS / JS на вкладке "Конструктор"). Код выполняется в изолированном iframe поверх/под/в выбранной области попапа (весь попап / только шапка / только тело с настройками — выбирается отдельным полем "Область", не связано с самим кодом).
Правила:
- Мой JS — это ТЕЛО функции с аргументами (root, canvas, storage, theme), не отдельный файл и не готовая функция целиком. НЕ оборачивай в "function(...) { ... }" — только само тело.
- root — DOM-элемент, в который вставлен мой HTML. Ищи элементы через root.querySelector(...).
- canvas — первый <canvas> из моего HTML, либо null, если его нет.
- storage — { get(key), set(key, value), remove(key) }, все три — Promise. Данные сохраняются между открытиями попапа (персистентно).
- theme — { accent, mod, pulse } — текущие цвета попапа (hex-строки), также доступны как window.SKYMOD_THEME.
- Если код запускает requestAnimationFrame / setInterval / addEventListener — ОБЯЗАТЕЛЬНО верни функцию очистки (return () => { ... }), которая всё это останавливает/снимает. Иначе при повторном "Применить" старый цикл продолжит работать параллельно с новым.
- Нет доступа к chrome.* API, к DOM самого попапа снаружи root, к DOM сайта, к внешним CDN-скриптам и веб-шрифтам — только чистые JS/Canvas/SVG/DOM в пределах root.
- Если используешь canvas — делай resize по clientWidth/clientHeight элемента (попап маленький и его размер может меняться), пример:
  function resize() { canvas.width = canvas.clientWidth; canvas.height = canvas.clientHeight; }
  resize();
  window.addEventListener('resize', resize);
- console.log/warn/error/info — попадают в панель "Консоль" на странице конструктора, ошибки (в т.ч. асинхронные и необработанные rejected promise) сами всплывают в "Отладчик" с номером строки — ничего специально ловить не нужно.

2) ГЛОБАЛЬНЫЙ CSS (поле "Свой CSS для всего попапа" на той же вкладке). Это НЕ песочница — CSS применяется напрямую к настоящему интерфейсу попапа, а не в iframe, поэтому им можно переопределить существующие стили и анимации SkyMod. Пример — переход между вкладками:
  .tab-content.slide-from-right { animation: slide-in-right .28s var(--ease); }
  .tab-content.slide-from-left  { animation: slide-in-left  .28s var(--ease); }
  .tab-content.fade-in          { animation: content-in     .22s var(--ease); }
Чтобы изменить анимацию перехода — переопредели @keyframes с тем же именем (slide-in-right / slide-in-left / content-in) под своим значением, или замени сами правила анимации на классах .tab-content.slide-from-right/.slide-from-left/.fade-in, при необходимости с !important. В этом поле никакого JS нет и не может быть — только валидный CSS.

3) ФОН САЙТА (секция "Фон сайта" на той же вкладке конструктора, свои поля HTML/CSS/JS). То же самое, что песочница попапа (п.1), только код выполняется не в попапе, а прямо на вкладке сайта avatar.skyeng.ru, пока она открыта. Отличия от п.1:
- theme здесь — { accent } (только один цвет, и он фиксированный: #8b7cf6; mod/pulse не существует на сайте). Цвет текущего занятия бери из schedule.color.
- Нет поля "Область" — всегда либо под интерфейсом сайта (как фон), либо поверх всего сайта, выбирается полем "Слой".
- В остальном (root/canvas/storage/аргументы, функция очистки, отсутствие chrome.*/внешних CDN, console.log/ошибки в свою "Консоль"/"Отладчик") — всё то же самое, что в п.1.
Обязательные правила для фона сайта (из реальных багов — нарушение любого из них ломает результат именно на сайте, хотя в предпросмотре всё выглядит нормально):
- ФОН ПРОЗРАЧНЫЙ, А ПОД НИМ БЕЛЫЙ САЙТ. Предпросмотр в конструкторе стоит на тёмной подложке, а на самом сайте под холстом ничего нет. Всё, что нарисовано полупрозрачным (свечения, частицы, линии с низкой альфой, режим 'lighter'), на сайте будет почти невидимо на белом. Поэтому ВСЕГДА рисуй собственный непрозрачный фон: каждый кадр начинай с ctx.fillStyle = '#цвет'; ctx.fillRect(0, 0, W, H) вместо одного clearRect (и/или задай background у canvas в CSS). Не полагайся на фон предпросмотра. Если нужен именно прозрачный фон, подбирай цвета и альфу под светлую подложку.
- РАЗМЕР В НАЧАЛЕ МОЖЕТ БЫТЬ НУЛЕВЫМ ИЛИ МЕНЯТЬСЯ. Никогда не генерируй позиции объектов (частицы, звёзды, капли) в абсолютных пикселях один раз на старте. Либо храни координаты в долях 0..1 и умножай на текущие W/H при отрисовке, либо при каждом resize пересчитывай позиции (масштабируй старые или создавай заново, если прошлый размер был 0). Количество объектов не считай от размера, который мог быть нулевым, без запасного минимума. Размер холста бери из window.innerWidth/innerHeight (iframe всегда на весь экран), а не из clientWidth, который в момент старта может вернуть 0.
- РАСПИСАНИЕ. В коде фона сайта есть 5-й аргумент schedule (живой объект: ready, phase "free|before|lesson|break|after", color (hex или null), dayProgress (0..1 или null), current/next/previous (title, subject, startLabel, endLabel, color, progress, minutesLeft, minutesUntil) и lessons). Читай поля прямо в кадре анимации. Расписания может не быть (ready === false, current/next/color равны null): всегда делай запасной цвет и нормальный вид. Не выдумывай других полей.
- РЕАКЦИЯ НА КУРСОР. Пока в конструкторе не включено "Взаимодействие с курсором", код фона не получает событий мыши вообще. Когда оно включено, страница пересылает в песочницу mousemove, mousedown, mouseup, click и mouseleave — их слушай как обычно: window.addEventListener('mousemove', e => { ... e.clientX, e.clientY ... }). Это работает при любом слое, включая "под интерфейсом", и не мешает кликам по самому сайту. Но кнопки, ссылки и поля ввода внутри самого фона кликать нельзя — фон только следит за курсором. Если анимация использует мышь, добавь в ответ напоминание, что нужно включить "Взаимодействие с курсором", и сделай так, чтобы без мыши (mouse.on = false) она тоже выглядела нормально.
- Холст должен занимать весь экран: position: fixed; inset: 0; width: 100%; height: 100%; display: block; pointer-events: none. Не используй z-index на холсте, слоем управляет поле "Слой" в конструкторе, а не код.
- Не рассчитывай на тяжёлые эффекты: фон работает на каждой вкладке сайта постоянно. Ограничивай devicePixelRatio до 2, число объектов держи в разумных пределах, для связей между частицами избегай O(n^2) на больших n.

ОБЩИЕ ПРАВИЛА ДЛЯ СТИЛЕЙ (CSS). Сначала пойми, ГДЕ именно будет жить CSS — от этого зависит, что он вообще может изменить. Три разных места, они не пересекаются:

А) "Свой CSS для всего попапа" (п.2). Применяется напрямую к настоящему интерфейсу попапа. Правила:
- Попап — окно фиксированных размеров, которые зависят от настройки «Размер попапа»: по умолчанию body шириной 400px, панель настроек .panel высотой 480px с прокруткой (overflow-y: auto); компактный вариант 320x420, максимальный 480x494. Размеры хранятся в переменных --popup-w и --panel-h. НЕ меняй width у body и height у .panel (высота зафиксирована специально — иначе Chrome неправильно пересчитывает размер окна попапа). Не используй 100vh/100vw, position: fixed на крупных блоках и height: 100% на body — размер попапа определяется содержимым, а не окном браузера. Для прокрутки длинного контента используй .panel, а не увеличивай высоту.
- У body стоит overflow: hidden и скругление — всё, что выходит за 320px по ширине, будет обрезано, а не прокручено. Не делай блоки шире попапа.
- Цвета интерфейса — это CSS-переменные: --accent, --accent-light, --accent-rgb, --accent-soft, --accent-bg, --accent-bg-soft (общий акцент), --mod, --mod-light, --mod-rgb, --mod-bg (цвет надписи Mod), а также базовые --bg, --bg-elevated, --bg-elevated-2, --text, --text-muted, --text-muted-2, --text-muted-3, --border, --radius-lg, --radius-md, --radius-pill, --ease. ПЕРЕМЕННЫЕ --accent*, --mod* расставляет скрипт попапа инлайном на html — обычное :root { --accent: red; } из твоего CSS их НЕ перебьёт и будет выглядеть как "ничего не происходит". Поэтому: чтобы использовать цвет акцента — бери var(--accent) / rgba(var(--accent-rgb), 0.3), а не задавай свой; чтобы задать цвет, не зависящий от выбора пользователя — пиши конкретное значение прямо в свойство элемента (color: #fff), а не через переопределение переменной. Переменные --bg, --text, --border и прочие неинлайновые переопределять можно, но тогда пиши :root { --bg: ... !important; } только если без !important не сработало.
- Твой CSS подключается после основного popup.css, но у многих правил попапа специфичность выше (вложенные и составные селекторы) — если правило не срабатывает, повысь специфичность или добавь !important. Не пиши !important на всё подряд сразу.
- Не прячи и не ломай интерфейс: не ставь display: none / visibility: hidden / pointer-events: none на .panel, .tab-content, вкладки и переключатели, не задавай opacity: 0 и z-index выше шапки без необходимости — пользователь не сможет открыть конструктор и отключить твой CSS (аварийный выход — выключить тумблер глобального CSS в конструкторе).
- Анимации: если меняешь переходы между вкладками — переопределяй именно @keyframes slide-in-right / slide-in-left / content-in или правила на .tab-content.slide-from-right / .slide-from-left / .fade-in. Не вешай transform, filter или will-change на body и на .panel без необходимости — это создаёт новый контекст наложения и ломает позиционирование и слои (в т.ч. слой песочницы конструктора), а filter/backdrop-filter на больших областях заметно тормозят попап.
- Только валидный CSS: никакого JS, никаких <style>-обёрток, никаких @import и внешних url() (шрифты, картинки по ссылкам могут не загрузиться) — если нужна картинка, используй data: URI.
- Не меняй шрифт всему попапу универсальным селектором, не проверив иконки и моноширинные поля; шрифт попапа по умолчанию — Manrope.

Б) CSS внутри песочницы (поле CSS в "Песочнице попапа" и в "Фоне сайта"). Это отдельный изолированный iframe — стили из него НЕ влияют на остальной интерфейс, и стили интерфейса не влияют на него. Правила:
- Селекторы вроде body .card, .topbar, .tab-content в этом поле бесполезны: в песочнице есть только тот HTML, что лежит в поле HTML. Чтобы изменить настоящий интерфейс попапа — это поле "Свой CSS для всего попапа" (А); чтобы изменить интерфейс сайта Skyeng — нужны настройки SkyMod на вкладках темы (цвета, фон, шрифт, карточки), через песочницу это невозможно.
- У html и body песочницы фон прозрачный, отступы нулевые, размер 100%, overflow: hidden. Для заливки задавай background на своём корневом элементе или на canvas (или на html, body в CSS песочницы), для полноэкранного холста: #id { position: fixed; inset: 0; width: 100%; height: 100%; display: block; pointer-events: none; }. z-index на холсте не нужен — слой выбирается полем "Слой" в конструкторе.
- В Фоне сайта iframe закрывает весь экран, а под ним белая страница сайта: ВСЕГДА задавай непрозрачный фон (background у холста/корня или fillRect в JS), иначе полупрозрачные эффекты станут почти невидимыми. Не полагайся на фон предпросмотра — он тёмный, а на сайте его нет.
- Для попапа песочница лежит на тёмном фоне попапа (#000), для сайта — на белом фоне страницы: не копируй цвета из одного режима в другой, не проверив контраст.
- Нельзя подключать внешние шрифты и CSS (@import, <link>, Google Fonts): используй системные шрифты (system-ui, sans-serif, monospace). Картинки — только data: URI или нарисованные в canvas/SVG.
- Единицы: в Фоне сайта vw/vh и проценты корректны (iframe на весь экран); в песочнице попапа учитывай, что область — 320px по ширине, а при выбранной области "шапка" или "тело" — ещё меньше.
- prefers-color-scheme и color-scheme в песочнице не используй: тема определяется только цветами из theme и твоим кодом.
- Анимации на CSS (@keyframes) допустимы и дёшевы; предпочитай transform и opacity, а не анимацию width/height/top/left, и избегай blur/filter на большой площади — Фон сайта работает постоянно на каждой вкладке.

В) Части интерфейса сайта (конструктор → режим "Сайт" → блок "Части интерфейса сайта"). Это РЕАЛЬНЫЙ CSS для конкретного элемента настоящего сайта avatar.skyeng.ru (в отличие от CSS песочницы, который сайта не касается). Работает только для частей из списка ниже; для каждой известны селекторы и свойства, которые сайт задаёт скриптом.
- Если пользователь называет часть по имени или синониму из списка (например, "лазер" или "сейчас"), пиши CSS ИМЕННО с её селекторами и соблюдай ограничения части.
- !important вручную не пиши: SkyMod сам усиливает селекторы и ставит !important на каждое объявление (кроме @keyframes, @font-face, @property и случая, когда в CSS есть комментарий /* skymod:raw */). Не используй [_ngcontent-...], [ng-c...] и хэш-классы, не меняй top/height/transform у элементов, которые двигает скрипт сайта.
- Формат ответа для части: ОДИН css-блок без пояснений внутри и явная подпись "для поля Части интерфейса сайта → название части".
- Если названной части нет в списке — НЕ выдумывай селекторы: попроси прислать outerHTML элемента и скриншот блока Styles из DevTools.
- Для простых вещей не нужен CSS: это готовые настройки SkyMod, предложи их. Вкладка «Расписание» в попапе: цвет, плотность и читаемость карточек, цвета предметов, полоска «сейчас», размытие и затемнение за окном занятия, свои блоки в расписании. Вкладка «Вид»: фон, шрифты. Вкладка «Удобство»: скрытие кнопки поддержки, аватарки с выходом, заголовка, меню и значка в шапке, защита от блокировки сайта, диагностика. Вкладка «Telegram»: напоминания о занятиях.
- У частей «Карточка занятия в расписании» и «Свой блок в расписании» кроме CSS есть вкладки HTML и JS (поведение). HTML это шаблон, вставляемый в каждую карточку (подстановки {{title}}, {{startLabel}}, {{minutesLeft}}, {{progress}} и др.). JS это тело функции с аргументом api (api.onCards, api.onHover, api.onLeave, api.onClick, api.card(id).addClass/removeClass/toggleClass/setVar/setData/setText); у него нет доступа к DOM сайта, он только отдаёт команды, которые превращаются в классы .skymod-is-имя, переменные --skymod-имя и атрибуты data-skymod-имя на карточке. Если задача про такое поведение, дай три блока css, html, js и назови часть. Полное описание API есть в кнопке «Скопировать промпт для ИИ: HTML и JS» у этой части в конструкторе: если его нет под рукой, не выдумывай методы api, а попроси его прислать.
- Галочка «Применять этот CSS и к своим блокам расписания» у части «Карточка занятия в расписании» переносит её CSS на свои блоки (карточка, название, время); отдельный CSS блоков пишется в части «Свой блок в расписании» и перебивает перенесённый.

Пресеты, экспорт и импорт

В левой колонке страницы конструктора — «Пресеты конструктора»: сохраняйте текущий код под своим названием прямо внутри расширения (без файлов), переключайтесь между несколькими заготовками, переименовывайте и удаляйте.

Отдельно — два уровня файлового экспорта/импорта:

  • «Экспорт/импорт в файл» (блок «Файл конструктора») — только код и настройки самого конструктора: HTML/CSS/JS, слой, область, глобальный CSS. Импорт полностью заменяет текущий рабочий код содержимым файла.
  • «Экспорт/импорт всех настроек» (блок «Все настройки SkyMod») — вообще всё: тема сайта, карточки, задания, попап и конструктор разом, одним .json-файлом. При импорте появляется список категорий с чекбоксами — можно снять галочку с того, что менять не нужно, и оно останется как есть в текущих настройках; применится только отмеченное.

Ограничения

  • Нет доступа к chrome.* API — нельзя читать настройки сайта, вкладки браузера и т.д. напрямую. Всё, что нужно из SkyMod, — это theme и storage.
  • Нет доступа к DOM попапа снаружи песочницы и к DOM самого сайта avatar.skyeng.ru.
  • Внешние скрипты по CDN в песочнице не загрузить (та же изоляция) — пишите чистым JS/Canvas/SVG.
  • Попап Chrome — маленькое окно (около 320px шириной), рассчитывайте макет на это.
Совет: если после включения конструктора попап выглядит сломанным — выключите тумблер «Включить конструктор» (это не стирает код) и проверьте отладчик и панель «Консоль» на вкладке — почти всегда причина видна сразу, с номером строки. Если сломался именно глобальный CSS (например, случайно скрыли весь интерфейс) — откройте попап, нажмите правой кнопкой → «Проверить» и выполните в консоли chrome.storage.local.set({builderGlobalCssEnabled:false}).
